[ADR-0002] Uso de Kong Api Gateway

Estado: Propuesto
Decisores: Arquitecto de Sistemas, Líderes Técnicos
Stakeholders: Equipos de Desarrollo Backend
Fecha: 2026-11-10
1. Contexto y Declaración del Problema

Para resolver el caso practico orientado a arquitecturas de microservicios, se requiere un componente central que
actúe como punto único de entrada para todas las peticiones de los clientes. El problema actual es definir cómo gestionar
de manera eficiente las preocupaciones transversales (enrutamiento, autenticación, rate-limiting, CORS y observabilidad)
sin acoplarlas a la lógica de negocio de cada microservicio.

Las fuerzas y limitantes relevantes para este entorno de capacitación incluyen:
Facilidad de despliegue: La herramienta debe poder levantarse rápidamente en entornos locales mediante Docker o Kubernetes 
sin consumir recursos excesivos.
Agnosticismo tecnológico: La solución no debe restringir el lenguaje de programación de los microservicios backend

2. Opciones Consideradas

Opción 1: Kong API Gateway (OSS)
Opción 2: WSO2 API Manager

3. Decisión Tomada
Decidimos seleccionar la Opción 1 (Kong API Gateway) porque ofrece un equilibrio ideal entre alto
rendimiento (basado en NGINX/OpenResty), agnosticismo de lenguaje

Razones Principales de la Elección

Razón 1: Permite utilizar un enfoque de configuración declarativa (YAML) mediante DB-less mode, lo que elimina la necesidad 
de desplegar y mantener una base de datos (PostgreSQL/Cassandra) durante los ejercicios prácticos de la capacitación.

Razón 2: Al ser tecnológicamente agnóstico, evita el "vendor lock-in" o la dependencia a un ecosistema de lenguaje específico,
permitiendo integrar microservicios modernos independientemente de si están construidos en Java, Node.js o Go.

Razón 3: Cuenta con un ecosistema de plugins "plug-and-play" (autenticación JWT, Rate Limiting, Prometheus) que permite a los
desarrolladores ver el valor inmediato de descargar responsabilidades transversales del código fuente.

4. Análisis Comparativo de Opciones (Pros y Contras)

Opción 1: Kong API Gateway

Ventajas:
Extremadamente rápido y ligero, ideal para arquitecturas modernas y contenerizadas.
Amplia gama de plugins de código abierto para cubrir las necesidades estándar de microservicios.

Desventajas:
La creación de plugins personalizados avanzados requiere conocimientos en Lua, Go o JavaScript.

Opción 2: WSO2 API Manager

Ventajas:
Solución "todo en uno" sumamente robusta que incluye gestión del ciclo de vida completo de la API, portal de desarrolladores,
análisis y un servidor de identidad integrado.

Desventajas:
Consumo de recursos significativamente mayor (JVM, múltiples componentes).
